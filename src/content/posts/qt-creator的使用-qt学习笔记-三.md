本节课是初学QT Creator的基本用法。
- **核心要点**  
  1. **Qt Creator 的定位与必要性**：本课程明确指出，手工使用记事本编写 Qt 程序代码效率低下、可维护性差、易出错，且难以扩展逻辑功能。Qt Creator 作为官方集成开发环境（IDE），其核心价值在于提供工程化、可视化、模块化的开发支持，显著提升开发效率与代码质量。  
  2. **“界面与逻辑分离”设计范式**：Qt Creator 最根本的设计哲学是将用户界面（UI）定义与业务逻辑实现彻底解耦。界面通过 `.ui` 文件（XML 格式）以声明方式描述，由 Qt Designer 可视化编辑；而逻辑代码则在 C++ 源文件（`.cpp`/`.h`）中独立编写，二者通过 `Ui::ClassName` 类型的指针进行桥接。该范式极大降低了代码耦合度，便于团队协作、界面迭代与功能测试。  
  3. **工程创建标准化流程**：创建新项目需严格遵循四步流程：（1）选择项目类型——推荐“Qt Widgets Application”，适用于传统桌面 GUI 开发；（2）命名与路径设定——项目名必须为纯英文（禁止中文及特殊字符），路径建议统一管理（如 `qt_online`）；（3）编译器配置——根据目标平台（Windows/Linux/嵌入式）自动识别或手动指定 MinGW、MSVC 或交叉编译工具链；（4）类模板选择——`QMainWindow`（含菜单栏、工具栏、状态栏的主窗口）、`QWidget`（轻量级无边框容器，适用于对话框或子窗口）、`QDialog`（模态/非模态对话框），本例选用 `QWidget`。  
  4. **项目文件体系结构解析**：一个标准 Qt Widgets 工程包含五大关键文件：（1）`.pro` 工程文件——控制构建配置（如 `QT += widgets` 声明依赖模块），仅在引入数据库、网络等高级模块时需手动修改；（2）`xxx.h` 头文件——定义类声明、继承关系（`class Widget : public QWidget`）、私有成员（`Ui::Widget *ui`）及信号槽声明；（3）`xxx.cpp` 实现文件——完成构造函数（含 `ui(new Ui::Widget)` 初始化列表）、析构函数（`delete ui`）及自定义逻辑；（4）`ui_xxx.h` 自动生成头文件——由 `uic` 工具将 `.ui` 编译为 C++ 代码，开发者无需直接编辑；（5）`xxx.ui` 设计文件——XML 格式存储控件布局、属性及层级关系，是 Designer 的唯一操作对象。  
  5. **Qt Designer 核心控件分类与用途**：控件按功能划分为六大类：（1）布局管理器（Layouts）——`QHBoxLayout`（水平）、`QVBoxLayout`（垂直）、`QGridLayout`（网格，适用于计算器等规则排列）、`QFormLayout`（表单，用于标签-输入框配对）；（2）间隔器（Spacers）——水平/垂直弹簧（`QSpacerItem`），用于动态分配空白区域，实现响应式缩放；（3）按钮组（Buttons）——`QPushButton`（通用命令按钮）、`QRadioButton`（单选）、`QCheckBox`（多选）；（4）视图组件（Views）——`QListView`/`QTableView`（数据模型绑定）、`QTreeView`（树形文件系统导航）；（5）容器控件（Containers）——`QGroupBox`（分组框）、`QTabWidget`（标签页）、`QStackedWidget`（堆叠窗口），用于组织复杂界面；（6）输入与显示控件（Input & Display）——`QLineEdit`（单行文本）、`QTextEdit`（多行富文本）、`QLabel`（静态文本/图像）、`QLCDNumber`（数字显示）、`QDateTimeEdit`（日期时间选择）。  
  6. **控件属性精细化配置方法**：所有拖入 Designer 的控件均具备完整属性面板（Property Editor），支持三类关键设置：（1）基础标识——`objectName`（C++ 代码中引用的唯一 ID，须语义化命名如 `cmdLineEdit` 而非默认 `lineEdit`）；（2）内容属性——`text`（标签文字）、`placeholderText`（输入框提示）、`icon`（图标资源）；（3）几何与样式——`geometry`（x/y/width/height 坐标尺寸）、`sizePolicy`（尺寸策略）、`minimumSize`/`maximumSize`（强制固定大小）、`font`（字体族、大小、粗细）、`alignment`（文本对齐方式）。  
  7. **布局嵌套与比例调控机制**：单一布局无法满足复杂界面需求，需采用嵌套策略（如外层 `QVBoxLayout` 包裹多个 `QHBoxLayout` 子布局）。布局内各控件占比通过 `stretch` 因子调控：选中布局后，在属性面板调整 `layoutStretch` 属性（逗号分隔数值序列），例如 `1,2,1` 表示中间控件占据总宽 50%，两侧各占 25%；弹簧控件（Spacer）的 stretch 值决定其吸收多余空间的能力。  
  8. **运行与调试基础流程**：首次构建需等待编译器生成全部中间文件（`moc` 元对象代码、`ui_*.h` 界面头文件），后续修改 `.ui` 文件后自动触发增量编译。运行前务必确认构建套件（Kit）已正确关联编译器与 Qt 版本，避免链接错误。当前界面虽可显示，但所有交互（如按钮点击）尚无逻辑响应，需后续通过信号与槽（Signal & Slot）机制连接事件处理函数。

- **关键结论**  
  1. Qt Creator 并非简单代码编辑器，而是融合了项目管理、可视化设计、智能编码、跨平台构建与调试于一体的全栈式开发平台，其工程化能力是 Qt 高效开发的前提保障。  
  2. “UI 与逻辑分离”不仅是技术实现方式，更是软件工程最佳实践——它确保界面设计师可独立优化视觉效果而不影响业务逻辑，程序员可专注算法实现而无需操心像素级布局，大幅提升开发敏捷性与可维护性。  
  3. `QWidget` 作为 Qt GUI 的基石类，其轻量性与灵活性使其成为绝大多数嵌入式 UI 与桌面工具的首选基类；而 `QMainWindow` 的完备框架更适合构建功能复杂的主应用程序。  
  4. `.ui` 文件的本质是界面元数据的 XML 序列化，其与 C++ 代码的松耦合设计，使得界面重构（如更换主题、适配高 DPI）仅需修改 `.ui` 文件，无需触碰一行业务逻辑代码。  
  5. 布局管理器（Layout）是 Qt 响应式设计的核心，彻底取代了传统绝对坐标定位（`setGeometry`），使界面能自动适应不同屏幕尺寸与字体缩放，这是现代 GUI 开发的必备能力。  
  6. 控件 `objectName` 的规范命名是信号槽连接与自动化测试的基础，未命名或命名混乱将导致 `findChild<T>()` 查找失败及后续逻辑开发受阻，必须作为开发纪律严格执行。  
  7. Qt Designer 的所见即所得（WYSIWYG）能力极大降低了 UI 开发门槛，但其本质仍是生成标准 C++ 代码，开发者仍需深刻理解底层 Qt 类继承体系（如 `QLabel` 继承自 `QFrame` → `QWidget` → `QObject`）以进行深度定制。  
  8. 当前完成的仅为静态界面原型，其商业价值取决于后续信号槽编程——将用户操作（如 `QPushButton::clicked()`）映射至具体业务函数（如 `on_commitButton_clicked()`），此为 Qt 开发从“能显示”迈向“可交互”的关键跃迁。

- **重要细节**  
  1. **命名规范强制要求**：项目名、类名、控件 `objectName` 必须严格遵循 C++ 标识符规则——仅含字母、数字与下划线，且首字符不能为数字；中文命名会导致编译器报错（`error: invalid character in identifier`）及 moc 工具解析失败。  
  2. **`Q_OBJECT` 宏的不可省略性**：任何需使用信号槽机制的类（如自定义窗口类）必须在私有区声明 `Q_OBJECT` 宏，否则 `connect()` 调用将静默失效，且 `moc` 工具无法为其生成元对象代码，此为 Qt 元对象系统（Meta-Object System）的硬性前提。  
  3. **`Ui::Widget` 指针的内存管理责任**：`ui(new Ui::Widget)` 在构造函数初始化列表中完成堆内存分配，`delete ui` 在析构函数中释放，此 RAII 模式确保资源不泄漏；若忘记 `delete ui`，将引发内存泄漏（Memory Leak）。  
  4. **布局嵌套的层级限制**：Qt Designer 支持无限层级嵌套，但过度嵌套会降低渲染性能并增加调试复杂度，建议单个容器内布局层数不超过 3 层，复杂界面宜拆分为多个 `QWidget` 子部件再组合。  
  5. **`QSpacerItem` 的不可见性本质**：弹簧控件在运行时完全透明，其作用是通过 `QSizePolicy::Expanding` 策略抢占布局剩余空间，开发者需通过观察控件相对位置变化来验证其生效，而非寻找可见元素。  
  6. **字体设置的双重路径**：`QLabel` 文字样式既可通过属性面板 `font` 属性全局设置，也可在代码中调用 `setFont()` 或 `setTextFormat(Qt::RichText)` 后使用 HTML 标签（如 `<b>加粗</b>`）实现动态样式，后者适用于需运行时切换样式的场景。  
  7. **坐标系原点约定**：Qt 所有控件的 `(x,y)` 坐标以父容器左上角为 `(0,0)`，x 轴向右递增，y 轴向下递增；`QPoint(180,50)` 表示距父窗口左侧 180 像素、顶部 50 像素的位置，此笛卡尔坐标系与数学惯例相反，需特别注意。  
  8. **首次构建耗时原因**：Qt Creator 首次编译需执行多项预处理：`qmake` 解析 `.pro` 生成 Makefile、`moc` 处理 `Q_OBJECT` 宏、`uic` 编译 `.ui` 为 C++、`rcc` 打包资源文件，此过程涉及大量 I/O 与代码生成，后续构建仅增量编译修改部分，速度显著提升。
